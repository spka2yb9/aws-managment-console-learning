# レッスン会話の文体ガイド

手本は「3分間ネットワーキング」(https://www5e.biglobe.ne.jp/aji/3min/) の会話。
毒舌な博士と、早とちりな生徒の掛け合いで、**正確な技術説明**を少しずつ積み上げる。地の文は 0 (会話・表・演習・クイズのみ)。

## 登場人物

### パス博士 (`hakase`、左・教授アイコン)
- 一人称「ワシ」。語尾「〜だ」「〜のだ」「〜おる」「〜かな？」。
- **毒舌で皮肉屋、ブラックジョーク好き**。ノード君をしょっちゅうからかうが、見捨てず最後まで説明する。
- 説明は正確で丁寧。大事なことは 2 回言う (「32 ビットだ。32 ビット。」のような強調ギャグ)。
- 昔話 (オンプレミス時代、深夜のデータセンター、手作業のサーバー調達、障害報告書) に脱線しがち。
- 失敗談は自分のものでも他人のものでも容赦なく笑いにする。

### ノード君 (`node`、右・若者アイコン)
- 新人エンジニア。素直だが早とちり、知ったかぶり、聞き間違い・ダジャレのボケをする。
- 知らない単語はひらがなでオウム返しして聞く (「でぃーえぬえす？」「えるしーゆー？」)。
- 理解したら **自分の言葉で言い換えて確認** する (「つまり、〜ってことですね」)。
- 前に習ったことを **「〜でしたよね」「Lesson 06 でやった〜ですよね」** と思い出して確認する。
- 博士の毒舌や脱線には **ツッコミ** を入れる (「関係ないですよね、それ」「今さらっと怖いこと言いましたよね」「なんで 2 回言ったんですか」)。
- 野望: いつか博士より給料をもらう (たまに口を滑らせる)。

## 会話の作り方

1. **ピンポン**: 1 発言は 1〜3 文。博士が長く語り続けず、ノード君の相づち・質問・言い換えを挟む。
2. **新しい単語は初めて出たその場で説明する**。演習の課題文・タスク・表・画面に出てくる単語も、演習の前の会話で説明しておく。
   - 聞き返し → 一言で定義 → たとえ話 (電話帳、住所、社員証、合鍵…) → 必要なら語源 (Apex = 頂点、octet = 8) の順。
   - 詳しくは後のレッスンでやるものは「それは Lesson 35 でやる」「今は〇〇とだけ覚えておけばよい」と断る。
3. **振り返り**: 以前のレッスンで出た言葉が出てきたら、ノード君が「〜でしたよね」と確認し、博士が一言で補足する。
   以前のレッスンの内容は、学習順 (`src/lessons/index.ts` の `COURSES`) で前にあるレッスンの会話・表・演習を根拠にする。無い内容を「前にやった」ことにしない。
4. **文脈**: レッスンの筋 (症状 → 調べる → 原因 → 直す → 確かめる) に沿う。唐突な話題転換をしない。脱線ギャグは 1〜2 往復で本題に戻る。
5. **ユーモア**: 1 つの会話ステップに最低 1 つ、毒舌・ブラックジョーク・ボケ/ツッコミを入れる。技術説明の正確さを犠牲にしない。
6. 書式: `**太字**` と `` `コード` `` が使える。コンソールの画面名・ボタン名は実際の日本語表示 (「インバウンドルール」「変更を保存」など)。AWS の API エラーは英語のまま引用する。

## ブラックジョークと毒舌の目安 (参照サイト並みの強さ)

- 「全部止めればコストはゼロだ。ついでに売上も、君の給料もゼロになるがな。」
- 「本番 DB を消した？ 安心したまえ、君の席も一緒に消えるだけだ。」
- 「障害報告書の書き方なら任せたまえ。ワシは経験豊富だからな。」
- 「バックアップがないなら、あとは祈るしかない。ワシは祈りの専門家ではないがな。」
- 「覚えておったか。昨日の君なら『えーぜっとって、味噌の銘柄ですか』と言っておったところだ。」
- 「君の記憶は揮発性メモリか。電源を切ると消えるタイプの。」
- 「インスタンスより先に、君の頭を再起動したほうがよさそうだ。」

参照サイトの台詞をそのまま使わない。同じ言い回しのギャグは全レッスンで 1 回まで (決め台詞として意図的に繰り返すもの以外)。

越えない線: 差別・容姿・実在の人物や企業への中傷・暴力・自傷。ブラックジョークの題材は **仕事と IT の惨事** (障害、深夜の呼び出し、始末書、減給、請求書、データ消失、上司の顔色) に限る。

## 例 (Lesson 35 の冒頭)

```
node:   博士、お客さんから「webapp-shop.example が開かない」って電話がありました。僕のブラウザだと www.webapp-shop.example は開けるんですけど…
hakase: ほう。www を付けると開いて、付けないと開かない、と。
node:   www なんて飾りみたいなものですよね？
hakase: 飾りではない。DNS から見れば、この 2 つはまったく別の名前だ。
node:   でぃーえぬえす？
hakase: ALB を作ったとき、「DNS 名がこの ALB の住所だ」と言ったのを覚えておるか。
node:   あ、あの長ーい名前ですね。web-alb-1234567890.ap-northeast-1.elb.amazonaws.com。
hakase: うむ。コンピュータは IP アドレスでないと相手を探せん。名前から IP アドレスを引く、電話帳のような仕組みが DNS だ。
node:   電話帳ですか。今どき見たことないですけど。
hakase: ……ワシの青春を否定するでない。
node:   じゃあ、www なしの名前は、電話帳に載ってないってことですか？
hakase: それを確かめるのが今日の仕事だ。
```

## 分量の目安

- レッスン冒頭 (最初の演習より前): 合計 15〜40 発言。1 つの会話ステップは 12 発言程度までにして、話の区切りで次の会話ステップに分ける。
- 演習の間にある既存の会話ステップ: 6〜15 発言。
- 正解時 (`ok(...)`): 2〜5 発言。何が起きたかを言い換えて確認 + 一言ジョーク。
- 不正解時 (`ng(...)`): 1〜3 発言。毒舌を入れてよいが、**次に何を見ればよいかのヒントを必ず含める**。
- クイズ: 問題文は博士の口調で。解説 (`explanation`) は 1〜3 発言。

## 実装上の制約 (テストを壊さないため)

- ステップの追加は **最初の演習/クイズより前だけ**。それ以降はステップを追加・削除・並べ替えせず、既存の会話ステップの発言を増やす・書き換えるだけにする (E2E は演習・クイズ・会話の並びに依存している)。
- 演習 (`exercise`) の `id` / `tasks` の `id`・`done`・`hotspotId` / `validate` の判定条件、クイズの `options` (文言は一字一句) と `answer` は変えない。
- 演習の `objective`・タスクの `title`・`hint` は、意味を変えない範囲の言い回し修正のみ。
- `ok(...)` / `ng(...)` の中身 (発言) は書き換えてよいが、単体テスト (`src/lessons/lessons.test.ts`) が正規表現で照合している文言は残す。
